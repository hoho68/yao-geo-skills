# 客户项目执行流程

这份流程给实际接项目时使用。它不要求客户懂代码，也不要求你一开始就改源码。

## 总原则

先判断项目处在哪个阶段：

- 没源码：做诊断和方案
- 有源码：先做 discovery
- 能创建 preview：只改 preview
- 客户确认前：不上线

## 流程 1：无源码项目

适用情况：

- 客户只给了网址
- 客户只有后台账号
- 客户还没准备源码
- 客户只是想先看看能不能做

工作步骤：

1. 填写 [客户项目资料表](client-project-intake-template.md)
2. 查看客户网站和参考网站
3. 做页面结构和视觉风格分析
4. 判断哪些内容适合 GEO 优化
5. 输出改造建议
6. 告诉客户：如果要进入真实模板预览，需要提供源码

可交付：

- 当前网站诊断
- 参考站风格拆解
- 页面模块建议
- GEOFlow 模板改造方向
- 源码交接清单

不做：

- 不承诺上线
- 不声称已经改好了模板
- 不要求客户直接给服务器密码

## 流程 2：有源码但未确认

适用情况：

- 客户给了 Git 地址
- 客户给了 ZIP
- 客户说“源码就在这个文件夹”
- 你还不确定它是不是 GEOFlow

工作步骤：

1. 把源码放到独立目录，例如 `D:\GEO\geoflow-app`
2. 按 [真实应用交接清单](geoflow-app-handoff-checklist.md) 检查
3. 只运行 discovery
4. 记录发现了什么框架和主题
5. 决定是否可以创建 preview

可交付：

- 源码接入检查记录
- GEOFlow 框架判断
- 主题发现结果
- 下一步 preview 建议

不做：

- 不直接改生产主题
- 不直接运行上线命令
- 不把源码复制进 `skills/` 或 `fixtures/`

## 流程 3：有源码且 discovery 通过

适用情况：

- 已确认是 GEOFlow
- discovery 能发现主题
- 客户允许做 preview

工作步骤：

1. 选择一个低风险目标主题
2. 创建 preview 主题
3. 第一刀只做很小的视觉切片
4. 只改 preview 主题
5. 更新 change-plan 和 preview-notes
6. 跑验证
7. 给客户看预览结果

可交付：

- 主题发现报告
- preview 主题
- 本次修改说明
- 风险边界说明
- 客户验收清单

不做：

- 不改 base 主题
- 不做 production activation
- 不改数据库、控制器、路由、登录、支付

## 流程 4：客户确认后准备上线

适用情况：

- 客户已经看过 preview
- 客户明确想上线
- 已经有备份和回滚方案

工作步骤：

1. 写上线前确认记录
2. 确认生产主题、备份方式、回滚方式
3. 明确谁负责上线
4. 先在测试环境验证
5. 再讨论生产激活

可交付：

- 上线前检查清单
- 回滚方案
- 客户确认记录

不做：

- 不口头确认就上线
- 不在不清楚当前 active theme 的情况下替换主题
- 不把 preview-ready 当成 production-ready

## 每次工作结束后要留下什么

至少留下三句话：

```text
这次完成了什么：
没有做什么：
下一步建议：
```

示例：

```text
这次完成了主题发现，发现当前项目是 Laravel GEOFlow，有 default 和 qiaomu-preview 两个主题。
没有做生产激活，也没有改 base 主题。
下一步建议：只在 qiaomu-preview 做一个首页 hero 的小切片。
```
